# Hermes Auto 多 Key 改造

范围：渠道内顺序轮询、独立凭证故障、429 冷却、Hermes Auto 容错。
不增加 Codex/Claude 接入、指纹伪装或 WebSocket。

## 交付阶段

- [x] 1. Key 数据表、旧数据迁移和单 Key 兼容（make check 通过）
- [x] 2. Key 管理 API、独立前端面板
- [x] 3. 两层调度、并发轮询
- [x] 4. 429 五分钟冷却、恢复和统一重试预算
- [x] 5. Key 日志、统计和探活
- [x] 6. Hermes 协议模拟集成回归
- [x] 7. 合并预览、v2 导入导出
- [x] 8. 全量检查和交付

每阶段运行 make check，提交并重启验证。真实供应商的付费调用和数据合并不自动执行。

## 冷却约定

429 按 Key + 模型独立记录：5、10、20、30 分钟递增，基础退避 30 分钟封顶；Retry-After 更长时遵守上游，持久化冷却最长七天。
冷却期间不得兜底选择，到期只允许一个恢复请求，成功清零。
整个请求最多三次上游尝试，同渠道最多两把 Key。Auto 会按策略继续尝试同渠道的其他允许模型，各模型共用次数与 Key 预算。输出后不得重放。

凭证版本只在替换或认证失效时变化；限流、模型权限及上游故障更新该模型的独立版本。模型恢复时保留版本记录，防止旧结果再次生效；不同模型同时失败均能记录冷却。

## 迁移与回滚

旧渠道一对一生成 Key，保留渠道 ID 和原 api_key 兼容字段。
多 Key 渠道不允许旧接口直接修改密钥，必须使用 Key 管理。
数据库首次迁移前使用 VACUUM INTO 在数据库同目录创建 pre-key-pool 时间戳备份。
回滚需停止应用并恢复该备份；升级后的新数据须另行保留。
同地址渠道不自动合并；源渠道合并后默认仅禁用，历史日志不重写。

## 使用与验证

- 添加供应商窗口：逐条填写或批量粘贴 Key，确认创建时与渠道原子保存。
- 编辑供应商窗口：直接管理当前供应商的 Key，支持批量添加、替换、停用、删除、调整顺序和查看冷却。Key 操作各自确认后立即生效，不随窗口取消撤销；渠道配置使用底部保存按钮。没有独立 Key 管理入口。
- 各个请求选用下一把可用 Key，不并行复制同一个请求。完整请求历史继续转发；模型切换不保证风格、缓存或供应商私有会话状态一致。
- 401 标记凭证不可用；403/404 对当前模型暂避两分钟。面板可用数是凭证层状态，不代表所有模型都可调用。
- 手动测试需确认可能消耗额度；已停用渠道及无效凭证不会参与测试；显式手动测试可检查冷却中的模型。选用次数包括诊断选 Key，限流轮次按生效的冷却窗口计数，不是每条并发 429 的次数。
- 设置 → 存储：脱敏配置仅供查看；含 Key 备份需确认，才能用于恢复。v1/v2 导入均先预览、原子追加，不覆盖旧渠道；只备份渠道配置，不包含全局设置、网关密钥或日志。
- 合并要求地址、协议与模型配置一致；预览后配置变化会拒绝提交。源渠道和日志保留，复制/合并保留密钥冷却及模型暂避状态。
- 测试使用本地模拟上游，覆盖工具调用历史、轮询、限流切换、全冷却、三次预算、流内错误、取消与总时限。没有运行真实 Hermes/供应商付费端到端测试。

## 边界

多 Key 只能分摊独立密钥额度；同账号/IP/供应商共享配额时不能保证绕开限流。本版按 Key + 模型冷却，不自动推断供应商共享额度或充值状态。不实现指纹伪装、Codex/Claude 专用会话绑定或 WebSocket 恢复。
注入检测为独立诊断路径，其报告不提供完整 Retry-After；报告中的 429 使用上述基础退避。网关转发与主模型探活遵守上游 Retry-After。
